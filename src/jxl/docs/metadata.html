api

edit

New bytes with the metadata and the container's framing changed as asked. The codestream and every other box stay exact. A file above maxInputBytes refuses JXL_LIMIT. An invalid JPEG XL signature refuses JXL_INPUT.

function edit(input: Uint8Array, changes: EditChanges): Promise<Bytes>

header

The image header, read synchronously from a file or its first bytes, with no pixel decoded: a container is read up to the box the input cuts, under every container rule those bytes decide, and at most 64 KiB of a codestream split in parts is joined. Up to the format's 2^30 pixels a side. Refuses when the header itself is not all there. A JPEG XL file only: inspect reads a JPEG's or PNG's header. Caller bytes use plain Uint8Array. SharedArrayBuffer backing is refused at runtime with JXL_INPUT. Unknown header options refuse JXL_OPTIONS.

function header(input: Uint8Array, options?: HeaderOptions): Omit<ImageHeader, 'icc'>

inspect

The image header after complete JPEG XL container framing is admitted, with details on request: 'metadata' (Exif, XMP and JUMBF) and 'layout' (boxes, fragments and codestream). This does not validate compressed pixel data. Also reads a JPEG's or PNG's intrinsic size, orientation, sample depth and color statement up to its first scan. An embedded profile is read and grayscale stays grayscale. These source formats take no details. Invalid details or decompress options refuse JXL_OPTIONS. A file above maxInputBytes refuses JXL_LIMIT.

function inspect(input: Uint8Array, options?: InspectOptions): Promise<ImageInfo>

InspectOptions

  • details? readonly ('metadata' | 'layout')[]

    'metadata' reads Exif, XMP and JUMBF. 'layout' reads the container's boxes and codestream. None by default.

  • decompress? BrotliCodec | undefined

    A Brotli decoder for compressed metadata the built-in reader does not take. Used with details metadata.

placeholder

A complete JPEG XL file of a VarDCT still's 1:8 image, cut from the file or from its first bytes once they hold the LF groups, without decoding. A prefix before them refuses JXL_INPUT. A Modular, animated or framed file, or one with alpha, JXL_UNSUPPORTED.

function placeholder(input: Uint8Array, options?: PlaceholderOptions): PlaceholderResult

PlaceholderOptions

  • format? "jxl" | "dataUrl"

    'jxl' (default): the file's bytes. 'dataUrl' adds a data:image/jxl URL of them.

slice

A complete JPEG XL file of one of a VarDCT still's sizes, cut from the whole file without decoding: encode with progressive: true for 1:4 and 1:2. Refuses what placeholder() refuses.

function slice(input: Uint8Array, options?: SliceOptions): SliceResult

SliceOptions

  • scale? 1 | 2 | 4 | 8

    The size wanted: 1, 2, 4 or 8 (1:8 is every VarDCT file's, 1:4 and 1:2 a progressive file's). A missing one refuses JXL_UNSUPPORTED.

  • maxWidth? number

    The smallest size at least this many pixels wide.

  • maxBytes? number

    The largest size in at most this many bytes. None refuses JXL_LIMIT.

sourceMetadata

The Exif and XMP a JPEG, PNG or WebP file carries, ready for edit, with the Exif orientation set to normal for pictures whose pixels were already turned upright. Nothing is decoded. A file of another format refuses JXL_INPUT.

function sourceMetadata(input: Uint8Array | Blob): Promise<{exif?: Uint8Array; xmp?: string}>

stream

A raw codestream wrapped in a container as it streams, chunk by chunk. Unsupported stream options refuse JXL_OPTIONS. Invalid chunk iterators or chunks refuse JXL_INPUT.

function stream(source: Iterable<Uint8Array> | AsyncIterable<Uint8Array>, options?: ContainerStreamOptions): AsyncGenerator<Bytes>

ContainerStreamOptions

  • chunkSize? number

    Encoded bytes per jxlp box. Defaults to 65536. A positive safe integer.

  • maxBytes? number

    Optional positive safe-integer budget for total container bytes. Defaults to available memory.

  • maxBoxes? number

    Maximum input and authored output boxes, including ftyp and level. None by default.

  • signal? AbortSignal | undefined

    Aborts the call. It throws the signal's reason.

  • level? 5 | 10

    Required codestream level. Level 10 writes jxll immediately after ftyp. Defaults to 5.

    The image header: header() returns it, inspect() adds the details asked for, and decode() returns it as header. reconstruction: a JPEG reconstruction box was among the bytes read (on a file's first bytes, false says nothing).

  • ImageInfo

    What inspect reads with no pixel decoded: the image header, and each detail asked for.     details: 'metadata' (Exif, XMP, JUMBF) and 'layout' (the container: boxes, fragments, the codestream). None by default: the header alone, no metadata inflated, no copy of the codestream.

    The header alone, read synchronously (jpegxl/metadata header): no metadata is read, so no maxMetadataBytes.

  • EditChanges

    At least one defined edit is required. Input limits alone request no change.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
