api

capture

The screenshot encoder in one file: a page's calls run in its own worker. Calls in a worker, Node and edge hosts run in place. 8-bit sRGB or Display P3 RGBA, exact or within maxError. Efforts 1-5. jpegxl/capture-complete adds photographic fidelity, efforts 6-9 and WebGPU. Invalid options refuse JXL_OPTIONS, unsupported efforts and textures JXL_UNSUPPORTED, and unreadable canvas data JXL_PLATFORM.

const capture: ResumableFunction<(input: CaptureInput, options?: CaptureOptions) => Promise<EncodedResult>>

CaptureOptions

  • transfer? true | undefined

    true: the call takes the pixels' ArrayBuffer (an animation's frames') instead of copying it. The caller's buffer is empty afterwards. A call refused leaves it as it was. A SharedArrayBuffer is refused with JXL_INPUT.

  • fidelity? CaptureFidelity

    'exact' (default), or {maxError} 0 to 8: every sample within that many levels of the input.

  • effort? CaptureEffort

    1 (fastest) to 5 (smallest file). Default 3.

Also takes signal, onProgress, maxPixels, onPreview, readAs: shared options.

close

Ends this module's worker and helpers. The next call starts them again. In place it does not wait for or cancel a call already running, configured or not.

function close(): Promise<void>

configure

This module's settings for the calls that follow. In a browser they are its queue's: the module runs in its own file's worker on a page. Inside a caller-owned worker it runs in place without starting a nested worker. Configure before the first call, or again once close() has resolved. In place (Node, Deno, Bun, edge hosts, a page's own worker) it takes the same keys: maxPixels, and maxPendingJobs bounding the calls pending at once. No worker starts and nothing is copied there, so the worker settings and maxPendingBytes have nothing to act on. Configuring while a configured call runs refuses JXL_OPTIONS. An unconfigured call keeps running unchanged, and the settings apply to the calls after it.

function configure(settings?: Omit<CodecConfig, 'webgpu' | 'helpers'>): void

prepare

Compiles the kernels and warms the coder, with no job.

function prepare(): Promise<void>

supported

True when this realm runs the capture encoder. supported('webgpu') is false: captures run on WebAssembly only.

function supported(feature?: 'webgpu'): Promise<boolean>

types

  • CaptureInput

    Input admitted by the lean screenshot encoder. GPU textures belong to capture-complete.

  • CaptureOptions

    A capture runs on WebAssembly. The pixels say their colorSpace, readAs reads a canvas, bitmap or Blob in a chosen one. effort: 3 by default. Higher is slower and smaller, with the same pixels at the same quality, and each effort writes its own file. A module refuses an effort it does not carry (JXL_UNSUPPORTED) and names the module that does. Every module that carries an effort writes the same file for the same call. jpegxl/capture and upload's capture run on WebAssembly and take no webgpu. Capture-complete's is CapturePhotoOptions.webgpu.

  • CaptureFidelity

    Within each sample of the input by maxError (0-8), or exact.

  • MaxError

    A capture's fidelity: 'exact' (the default), or every sample within maxError of the input. 0 is 'exact'.

  • ImageInput

    What an encode, fit or variants call reads: pixels, a decode result, a canvas, bitmap, video frame, Blob, rows or a GPU texture.

  • CapturePixels

    A capture takes straight RGBA8, not the deeper sample descriptions accepted by encode.

  • Bytes

    Library-produced bytes own an ArrayBuffer. Caller byte inputs accept plain Uint8Array.

  • ImagePreview

    A complete candidate, before the final result. Its bytes belong to the observer. Measurements contain only scores already computed for this file. Candidates can grow or lose quality while the encoder searches.

  • PreviewOptions

    Latest only, at most every 100 ms. A returned promise delays the next preview. Delivered observers settle before success, unless aborted, and thrown or rejected values reject the operation unchanged. Undelivered previews are discarded on completion or cancellation. The final result is separate.

  • ImageJob

    An ordinary image operation. The original is supplied separately to the chosen execution host.

  • ImageVerb

    The call that made a result: encode, fit, variants, capture, recompress, restore or another verb.

  • Digest

    SHA-256 of the identified bytes or canonical sample description and pixels.

  • ResultSource

    What the result was made from: bytes or pixels, and the SHA-256 of them.

  • ResultReason

    A requested target could not be met. Codes keep their ordinary meanings.

  • ResultTransform

    The transform applied to the original for this output: our area average in linear light to width and height.

  • ResultFidelity

    The fidelity the file was made at, or for a fit the range it was searched in.

  • ResultMeasurement

    Measurements already made by the encoder, or attached by an independent verifier. The domain names what was measured. 'predicted' is not a measurement: the target a lossy effort 1-5 file aimed at, as its floor, with no score (no meter ran), at every depth and quality. A lower bound uses floor and an upper bound uses limit. Explicit S2 targets at efforts 1–5 report a guarded reconstruction score: a lower bound for the browser-decoded picture.

  • ImageResult

    One record per requested output, shared by ordinary calls and queues. Only fit and variants can resolve without a file. A preserved JPEG has kept: 'jpeg-bytes', fidelity: 'exact' and measurements: []: the original JPEG restores exactly, with no claim of a measured score. Empty measurements add no independent verification claim. An encode can return meetsTarget: false with bytes when its measured look target was missed. An unmet size target (fit, variants) returns meetsTarget: false without a file.

  • EncodedResult

    A result that always holds a file: what encode, capture, recompress, restore, format and animation's encode resolve with.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.

JPEG XL exports for SnapDOM 3

SnapDOM page

This example uses jpegxl 8.4.0 or later. Copy jxl.js and jxl.d.ts together, then use SnapDOM's plug-in interface:

import {snapdom} from '@zumer/snapdom';
import {jxl} from './jxl.js';

const result = await snapdom(document.querySelector('#card'), {plugins: [jxl()]});
const file = await result.toBlob({format: 'jxl'});
const image = await result.toJxl({quality: 0.8, effort: 3});
await result.download({format: 'jxl', filename: 'card'});

capture-complete writes one JPEG XL file with lossy photos and exact text. For every pixel exact, export with quality: 1, or ship the smaller exact-only module:

import * as capture from 'jpegxl/capture';
jxl({module: 'jpegxl/capture', codec: capture});

A build holds only the module you choose. The plug-in imports capture-complete itself. capture and upload come only as the codec you import. Transparent samples (a card's rounded corners) stay transparent, as in SnapDOM's PNG, unless you set backgroundColor. Crop a capture with SnapDOM's clip.

Options and defaults

The port uses these names throughout 8.x. The runtime and TypeScript checks beside the source protect this boundary.

  • jxl() option module

    Default 'jpegxl/capture-complete'

    Meaning Capture-complete carries efforts 1–9. 'jpegxl/capture' carries exact capture at 1–5. 'jpegxl/upload' carries photographic capture at 1–3. The last two need their codec.

  • jxl() option codec

    Default jpegxl/capture-complete, imported on the first export

    Meaning The capture module you imported, or any object with its prepare and capture.

  • jxl() option effort

    Default The module's default, 3

    Meaning Default for each export. That export's effort overrides it.

  • jxl() option webgpu

    Default Omitted

    Meaning jpegxl/capture-complete only: left out, it uses a device where it helps. false turns it off. 'required' refuses without one. jpegxl/capture and jpegxl/upload run on WebAssembly and refuse it.

Helpers are the module's own setting: import {configure} from 'jpegxl/capture-complete'; configure({helpers: true});.

  • Export option quality

    Default or handling 0.92. Values below 1 become fidelity: {quality: Math.max(1, quality * 100)}. 1 is exact. The exact module stays exact at every quality. A card with no photograph stays exact too: quality changes nothing there.

  • Export option scale

    Default or handling 1. Forwarded to SnapDOM. An explicit width or height takes precedence.

  • Export option width, height

    Default or handling Unset. Forwarded to SnapDOM. Setting only one keeps the aspect ratio.

  • Export option dpr

    Default or handling window.devicePixelRatio through SnapDOM. The returned image takes the drawn canvas's CSS size. A direct hook call with no dpr uses 1. Downloads use dpr: 1.

  • Export option backgroundColor

    Default or handling SnapDOM's own: transparent, as its PNG. Set a color to fill.

  • Export option effort

    Default or handling The jxl() preset, otherwise 3. Read from the export's options (a beforeExport plug-in may change them), then its request.

  • Export option signal

    Default or handling None. Cancellation preserves signal.reason, including while drawing and preparing the image.

  • Export option onProgress

    Default or handling None. Receives an encoding fraction from 0 to 1, after drawing.

  • Export option onEncoded

    Default or handling None. Receives {exact: boolean, textMarks?: 'skipped'} once for the selected file. A callback exception rejects the export.

  • Export option format

    Default or handling toJxl() selects JPEG XL. toBlob({format: 'jxl'}) selects it case-insensitively, as does SnapDOM's older type: 'jxl' when no format is set. Other blob formats delegate to SnapDOM. The download hook defaults to PNG.

  • Export option filename

    Default or handling 'snapDOM' through SnapDOM. A direct call to the download hook falls back to 'snapdom'. A missing recognized image extension gets the selected format's extension.

jpegxl calls the port consumes

  • Module and name jpegxl/capture-complete

    Arguments The only module the plug-in imports, on the first export. With your own codec it imports none. In a browser it runs in its own worker.

    Return fields used prepare(): Promise<void> and capture(input, options): Promise<ImageResult>. Preparation is a warm-up. Its failure is handled by the capture.

  • Module and name Encoder: capture

    Arguments The drawn canvas. {fidelity, effort?, webgpu?, signal?, onProgress?, exactRects?, photoRects?, textComplete?}

    Return fields used meetsTarget: boolean, bytes: Uint8Array and kept on success. reason: {code, message} on a miss. A miss rejects the export with that code and message. The Blob contains only the returned byte view.

  • Module and name jpegxl/page-rects: measure

    Arguments The captured element. {edges, keep}: edges except for the upload module, and keep, the nodes SnapDOM cloned.

    Return fields used A measurement with box: {left, top, width, height}, text, photos, textComplete: true, and optional edges. The example reads box.width and box.height and passes the measurement to pageRects.

  • Module and name jpegxl/page-rects: pageRects

    Arguments The measurement, {width, height} canvas, and {area: {x?, y?, width?, height?}, edges}. Area is in CSS pixels. Defaults cover the measured element.

    Return fields used {exactRects, photoRects} arrays in whole canvas pixels, plus textComplete: true when carried by the measurement. Rectangles have {x, y, width, height}. Exact rectangles may also have solidText or edge.

  • Module and name Display decoder: jpegxl/decode

    Arguments Imported only if a lossy file cannot display natively. In a browser it runs in its own worker.

    Return fields used decode(blob, options): Promise<DecodedImage>.

  • Module and name Decoder: decode

    Arguments The JXL Blob. {format: 'uint8', colorSpace: 'srgb', maxPixels: 268435456, signal?}

    Return fields used {data, width, height}. Build the RGBA view with new Uint8ClampedArray(data.buffer as ArrayBuffer, data.byteOffset, data.byteLength).

Measurements are taken in afterClone, before the page can change. The export maps them through the capture's viewBox, clip and scale. Below 1:1, text boxes round outward. When photos remain, the smaller of photographic and whole-exact capture wins. Without a measurement, the whole capture stays exact.

The plug-in carries measurement completion automatically. Custom integrations forward the whole pageRects result, including textComplete and an empty exactRects array. The marker comes from measure. A hand-built or partial measurement leaves it absent. A solid-text box over a region coded as a photo stays exact in full, including its background.

Efforts 6–9 need no JPEG XL decoder: with text and photo rectangles, jpegxl measures photos on the encoder's own reconstruction.

SnapDOM calls and return shapes

jxl() returns {name: 'jxl', pure: true, afterClone?, defineExports}. Equal options return the same plug-in. Exact capture has no afterClone hook. The hook reads context.element, context.nodeMap and context.outerTransforms. Exports read context.meta's contentX, contentY, vbW, vbH, clip, targetW and targetH, context.width and context.height, and context.export.requestedOptions. pure: true keeps SnapDOM's memoization: the measurement depends on the DOM alone.

defineExports({exports}) uses exports.canvas(options): Promise<HTMLCanvasElement> and exports.blob(options): Promise<Blob>. It returns:

  • Hook jxl(context, options = {})

    SnapDOM result method toJxl(options)

    Return Promise<HTMLImageElement>

  • Hook blob(context, options = {})

    SnapDOM result method toBlob(options)

    Return Promise<Blob>. JPEG XL has MIME type 'image/jxl'

  • Hook download(context, options = {})

    SnapDOM result method download(options)

    Return Promise<void>

toJxl() first displays the JPEG XL file. Where the browser cannot show JPEG XL, the image is a PNG preview, not the file: of the drawn canvas for an exact capture, of the decoded file for a lossy one. The saved Blob remains JPEG XL. Downloads use a file share sheet where supported on iOS, otherwise a browser download.

jxl.d.ts exports jxl, JxlOptions, JxlExportOptions, JxlContext, JxlPlugin, SnapDOMExports, CaptureEncoder, CaptureHelpers, CaptureModule, LeanCaptureModule, CompleteCaptureModule, CaptureEffort, UploadEffort, and Effort. It adds the three JPEG XL result methods to SnapDOM's CaptureResult type.
