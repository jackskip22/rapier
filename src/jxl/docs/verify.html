configureDecoder

In a browser, direct verify() reads 8-bit sRGB and Display P3 stills with the browser's own JPEG XL decode, and direct verify() in Node, Deno and Bun needs nothing. Resumable verification (jpegxl/resumable with verify), and elsewhere for recompressed JPEGs, row sources, animations, more than 8 bits, float samples or other color, the one setup step is configureDecoder(decode, restore) with jpegxl/decode's decode and jpegxl/jpeg's restore. Without it those refuse JXL_PLATFORM, naming it. One call serves every jpegxl module.

function configureDecoder(decode: PackageDecode | null, restore?: JpegRestore | null, recompress?: JpegRecompress | null): void

verify

Restore and compare a JPEG, compare exact decoded samples, or measure the decoded lossy output against its declared target, plus every explicitly protected sample. Rejects with an existing JXL_* code. A failed comparison includes error.verification. The original and result are snapshotted at the call. This module never writes, replaces, or deletes a file. Invalid protection refuses JXL_OPTIONS. Incompatible JPEG verification refuses JXL_UNSUPPORTED. Missing JPEG reconstruction refuses JXL_RECONSTRUCTION.

function verify(original: ImageInput | AnimationInput | Uint8Array, output: ImageResult, options?: VerifyOptions): Promise<VerificationReceipt>

types

  • VerifyProtection

    Explicit exact-pixel obligations in output-canvas coordinates, snapshotted at verify(). Applies to an unrotated still raster, including a transformed still reference. Supply the actual selected mask for conditional text or edge protection. Hints are not masks.

  • VerifyOptions

    One binary byte per output pixel, 1 = exact. The selection unions with exactRects.

  • ProtectionEvidence

    Pixels that must decode exactly, whatever the output's fidelity.

  • VerificationReceipt

    Independent evidence bound to the original and the actual output file.

  • FailedVerificationReceipt

    Available on a failed comparison when the original and output were admitted.

  • VerificationError

    What verify rejects with: a JXL_ code, and the failed receipt when the comparison ran.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
