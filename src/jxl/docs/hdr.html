read

Read an OpenEXR (.exr) or Radiance (.hdr) file. Errors carry the encoder's codes: JXL_INPUT (malformed, or a feature named in the message that is not read), JXL_OPTIONS (invalid options), JXL_DIMENSIONS (invalid dimensions or the caller's maxPixels), JXL_MEMORY (host allocation refusal), JXL_IO (file read failure), JXL_PLATFORM (missing host API). OpenEXR: scan-line and tiled files (level 0 of mip and rip maps), the first image part in multi-part files. HALF or FLOAT R, G, B or Y with optional A, and luminance-chroma Y, RY, BY. Other channels are skipped. NONE, RLE, ZIPS, ZIP, PIZ, PXR24, B44, B44A, DWAA and DWAB. Refused by name: HTJ2K, LJ2K and ZSTD compression, deep files, UINT color or alpha, and subsampled color other than 2-by-2 RY/BY with full-size Y. Radiance: RGBE, either Y-row order and either X-column order, new run-length or flat rows. EXPOSURE and COLORCORR are not applied. Refused: XYZE, old run-length rows and X-major files. ZIP data is inflated by the platform's DecompressionStream, so the realm needs it (browsers, workers, Node 18+, Deno, Bun, Cloudflare Workers). A picture the host cannot hold refuses JXL_MEMORY.

function read(input: Uint8Array | ArrayBuffer | Blob, options?: HdrOptions): Promise<HdrPicture>

HdrOptions

  • window? 'data' | 'display' | undefined

    OpenEXR only. 'data' (default) is the pixels the file stores. 'display' is its display window, transparent black where the data window does not reach.

  • maxPixels? number

    Optional caller ceiling in pixels. A picture above it refuses JXL_DIMENSIONS. Without it, only the host's allocation limits apply.

types

  • HdrPicture

    The picture record encode takes, read from a file: RGBA, straight rows, linear light, exact samples. sampleFormat is 'float16' (raw binary16 words in a Uint16Array) when every sample is exactly a half, else 'float32'. A picture without alpha has alpha 1. Nothing is tone-mapped, converted or scaled.

  • HdrOptions

    Number of parts in a multi-part OpenEXR file. The first image part supplies the picture.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
