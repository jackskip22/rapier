api

close

Ends this module's worker and helpers. The next call starts them again. In place it does not wait for or cancel a call already running, configured or not.

function close(): Promise<void>

configure

This module's settings for the calls that follow. In a browser they are its queue's: the module runs in its own file's worker on a page. Inside a caller-owned worker it runs in place without starting a nested worker. Configure before the first call, or again once close() has resolved. In place (Node, Deno, Bun, edge hosts, a page's own worker) it takes the same keys: maxPixels, and maxPendingJobs bounding the calls pending at once. No worker starts and nothing is copied there, so the worker settings and maxPendingBytes have nothing to act on. Configuring while a configured call runs refuses JXL_OPTIONS. An unconfigured call keeps running unchanged, and the settings apply to the calls after it.

function configure(settings?: Omit<CodecConfig, 'webgpu' | 'helpers'>): void

Compiles the WebAssembly kernels recompress needs. restore needs none.

recompress

A phone's HDR photo (Ultra HDR, ISO 21496-1) keeps its gain map where every decoder that shows HDR reads it: the jhgm box, its metadata in ISO 21496-1 form. restore still returns the exact JPEG. Facts.otherDecoders counts the bytes another decoder's JPEG leaves out (the gain map JPEG). A photo without one is recompressed as without the option.

restore

The JPEG a recompressed file was made from, restored exactly. A file with no reconstruction data refuses JXL_RECONSTRUCTION. jpegxl/metadata header(bytes).reconstruction says, without a decode, whether the bytes hold a reconstruction box. restore alone says whether the JPEG comes back. Unknown restore options refuse JXL_OPTIONS.

types

  • RecompressOptions

    In one file: a page's calls run in its own worker. Calls in a worker, Node and edge hosts run in place. A JPEG's coefficients coded as JPEG XL with no loss, with what restore needs to write the same JPEG back. The input and options are taken at the call. effort is 7 unless given. maxPixels (no default) bounds the JPEG's size, and restore's (JXL_DIMENSIONS). An input the host cannot hold refuses JXL_MEMORY. Combined APP, COM, inter-marker and inline-tail reconstruction payload above 64 MiB refuses JXL_JPEG. Caller bytes use plain Uint8Array. SharedArrayBuffer backing is refused at runtime with JXL_INPUT. Invalid options refuse JXL_OPTIONS, oversize pictures JXL_DIMENSIONS, and unavailable SIMD JXL_WASM.

  • JPEGOptions

    JPEG recompression runs on WebAssembly.

  • JobOptions

    maxPixels: the largest picture this call admits, the caller's bound. None by default. A side is at most 2^30 (the JPEG XL size field). Under configure's the smaller of the two holds. Above 40,000,000 an encode or capture is coded in bands of about 4 MP, composed as one still, so working memory stays about one band's beside the input. Where the host cannot hold the work, the call refuses JXL_MEMORY.

  • ImageJob

    An ordinary image operation. The original is supplied separately to the chosen execution host.

  • ImageVerb

    The call that made a result: encode, fit, variants, capture, recompress, restore or another verb.

  • Digest

    SHA-256 of the identified bytes or canonical sample description and pixels.

  • ResultSource

    What the result was made from: bytes or pixels, and the SHA-256 of them.

  • ResultReason

    A requested target could not be met. Codes keep their ordinary meanings.

  • ResultTransform

    The transform applied to the original for this output: our area average in linear light to width and height.

  • ResultFidelity

    The fidelity the file was made at, or for a fit the range it was searched in.

  • ResultMeasurement

    Measurements already made by the encoder, or attached by an independent verifier. The domain names what was measured. 'predicted' is not a measurement: the target a lossy effort 1-5 file aimed at, as its floor, with no score (no meter ran), at every depth and quality. A lower bound uses floor and an upper bound uses limit. Explicit S2 targets at efforts 1–5 report a guarded reconstruction score: a lower bound for the browser-decoded picture.

  • ResultOtherDecoders

    Another decoder (libjxl's djxl) returns this JPEG without its last missing bytes. Jpegxl/jpeg's restore returns all of it. 'past-jbrd': data after the JPEG's end travels outside the reconstruction box. This happens for tails longer than the 4,260,096 bytes the box holds, or when gainMap: true keeps the gain map in a jhgm bundle.

  • ImageResult

    One record per requested output, shared by ordinary calls and queues. Only fit and variants can resolve without a file. A preserved JPEG has kept: 'jpeg-bytes', fidelity: 'exact' and measurements: []: the original JPEG restores exactly, with no claim of a measured score. Empty measurements add no independent verification claim. An encode can return meetsTarget: false with bytes when its measured look target was missed. An unmet size target (fit, variants) returns meetsTarget: false without a file.

  • EncodedResult

    A result that always holds a file: what encode, capture, recompress, restore, format and animation's encode resolve with.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
