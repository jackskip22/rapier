api

install

Shows JPEG XL images where the browser does not: those on the page and those added later. Importing installs nothing. One installation a document: a later call returns it until disconnect(). refresh() rereads the page at once. Options are read once, at the call. Invalid ones reject with JXL_OPTIONS and leave any earlier installation connected.

function install(options?: PolyfillOptions): Promise<PolyfillController>

PolyfillOptions

  • document? Document

    The document to patch. Default the global one.

  • root? Document | Element | ShadowRoot

    Where to look for images: a document, element or shadow root. Default the document.

  • probeURL? string

    A JPEG XL data or image URL the native test loads. Default a built-in one.

  • force? boolean

    true decodes every image here, even where the browser shows JPEG XL itself. Default false.

  • workers? 1 | 2 | 3 | 4

    Images decoded at once, 1 to 4. Default 2.

  • maxDecodedBytes? number

    Bytes for decoded images, none by default: when set, each decode, one per worker at once, is bounded by it alone, and the images shown together stay under it. A decode holds about 32 bytes a pixel. A larger picture fails with JXL_DIMENSIONS, naming its size and this limit.

  • maxInputBytes? number

    Largest file fetched, in bytes. None by default. A larger one fails with JXL_LIMIT.

  • rootMargin? string

    How far off screen an image starts decoding, in pixels or percent. Default '1000px'.

  • workerFactory? (() => WorkerLike) | undefined

    Makes the decode worker. For a bundler or a Content Security Policy that needs your own URL.

  • decode? ((bytes: Bytes, options: DecodeOptions) => DecodedImage | PromiseLike<DecodedImage>) | undefined

    Your own decoder in place of the package's (a native or a server-side one): it receives owned bytes and may return the decoded image directly or asynchronously.

  • onError? ((error: unknown, element: Element) => void) | ((error: unknown, element: Element) => PromiseLike<void>) | undefined

    An image that could not be shown, with its ErrorCode: JXL_IO where the image request failed, JXL_PLATFORM where the page's image policy refuses decoded images or the decoded picture could not be put on screen. A value this callback throws or rejects is reported unchanged through the window's reportError.

supportsJXL

null means policy or a timeout prevented detection, not lack of native support. A document unable to create images, or a non-string probeURL, refuses JXL_OPTIONS.

function supportsJXL(document?: Document, probeURL?: string): Promise<boolean | null>

types

  • PolyfillOptions

    Options for install(). All are optional.

  • PolyfillController

    An image that could not be shown, with its ErrorCode: JXL_IO where the image request failed, JXL_PLATFORM where the page's image policy refuses decoded images or the decoded picture could not be put on screen. A value this callback throws or rejects is reported unchanged through the window's reportError.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
