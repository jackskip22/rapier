jpegxl

jpegxl: the full still encoder in one file: a page's calls run in its own worker.

ImportExampleAPITypesErrors

import

import {close, configure, configureDecoder, encode, fit, prepare, supported, variants} from 'jpegxl';

about 500 KB Brotli, about 620 KB gzip. One file, no dependencies.

example

import {writeFile} from 'node:fs/promises';
import {encode} from 'jpegxl';

const picture = {data: new Uint8Array([240, 120, 40, 255]), width: 1, height: 1};
const {bytes} = await encode(picture, {fidelity: {quality: 90}});
if (bytes) await writeFile('picture.jxl', bytes);

Takes RGBA {data, width, height}, ImageData, a canvas, an ImageBitmap, a VideoFrame, a Blob or a GPU texture, in 8 or 16 bits, Float16Array or Float32Array (HDR).

  • fidelity: {quality: 1–100}, default 90, or 'exact'.
  • effort: 1–9, default 7. Efforts 6–9 measure the look. Efforts 1–5 measure only where it earns its time.
  • webgpu: efforts 7–9 use WebGPU where it can. 'required' refuses without it. false turns it off.
  • progressive: true: the first bytes show the whole picture, which sharpens as the rest arrives (about 2 to 5% more bytes).
  • The host's memory is the limit.
  • A JPEG stays JPEG and restores exactly with fidelity: 'exact' or at a quality level when that can be smaller (efforts 6–9). jpeg: 'pixels' encodes its pixels.
  • jpegxl/animation takes frames or an animated GIF, jpegxl/hdr reads OpenEXR and Radiance files, jpegxl/verify checks a file against its source.

api

close

Ends this module's worker and helpers. The next call starts them again. In place it does not wait for or cancel a call already running, configured or not.

function close(): Promise<void>

configure

This module's settings for the calls that follow. In a browser they are its queue's: the module runs in its own file's worker on a page. Inside a caller-owned worker it runs in place without starting a nested worker. Configure before the first call, or again once close() has resolved. In place (Node, Deno, Bun, edge hosts, a page's own worker) it takes the same keys: helpers (where the module has them), webgpu and maxPixels, and maxPendingJobs bounding the calls pending at once. No worker starts and nothing is copied there, so the worker settings and maxPendingBytes have nothing to act on. Configuring while a configured call runs refuses JXL_OPTIONS. An unconfigured call keeps running unchanged, and the settings apply to the calls after it.

function configure(settings?: CodecConfig): void

configureDecoder

Where the host reads no JPEG (Node, Deno, Bun), the one setup step for a JPEG input: configureDecoder(decode, restore, recompress) with jpegxl/decode's decode and jpegxl/jpeg's recompress (restore may be null). Without it a JPEG refuses JXL_PLATFORM. One call serves every jpegxl module in the realm. null alone clears it, while null with helpers keeps them.

function configureDecoder(decode: PackageDecode | null, restore?: JpegRestore | null, recompress?: JpegRecompress | null): void

encode

jpegxl: the full still encoder in one file: a page's calls run in its own worker. Calls in a worker, Node and edge hosts run in place. Efforts 1-9, exact or lossy, and effort 10 exact. Measured fidelity, WebGPU at lossy efforts 7-9, HDR and deeper samples, ICC and codestream features. An exact, unchanged JPEG File or Blob preserves the original JPEG. At efforts 6-9, a JPEG look request compares the pixel result's size with reversible recompression. jpeg: 'pixels' requires pixel encoding. A preserved JPEG reports fidelity: 'exact', kept: 'jpeg-bytes' and measurements: [], with no measured score. An animation is encoded by jpegxl/animation. A file's header and metadata are jpegxl/metadata's. In a browser each module's own name is its worker queue (configure sets it). Page capture is jpegxl/capture and jpegxl/capture-complete. Invalid fidelity, effort or readAs refuses JXL_OPTIONS. A required WebGPU device or job that cannot run refuses JXL_WEBGPU.

const encode: ResumableFunction<(input: ImageInput, options?: EncodeOptions) => Promise<EncodedResult>>

EncodeOptions

  • transfer? true | undefined

    true: the call takes the pixels' ArrayBuffer (an animation's frames') instead of copying it. The caller's buffer is empty afterwards. A call refused leaves it as it was. A SharedArrayBuffer is refused with JXL_INPUT.

  • jpeg? 'pixels'

    Encode a JPEG's decoded pixels without reconstruction data. Omitted, an unchanged JPEG is preserved for 'exact'. A look request at efforts 6-9 compares reversible recompression with the pixel result.

  • effort? Effort

    1 (fastest) to 9 (smallest file). Default 7. Same fidelity, same file on every host.

  • progressive? boolean

    Lossy pictures in three passes over the 1:8 image (1:4, 1:2, then the rest): a browser loading the file sharpens it in steps, and jpegxl/metadata slice() cuts each size from it. The same picture in a file a few percent larger. A picture the encoder codes as graphics (Modular) keeps one pass. Exact fidelity refuses JXL_OPTIONS.

  • firstRegion? Region

    The groups covering this rectangle come first in the file, so a browser loading it shows the rectangle before the rest. The pixels are unchanged. Codestream settings (progressive, upsampling, ...) are format({kind: 'photo'})'s.

  • fidelity? PixelFidelity

    'exact', or {quality} from 1 to 100 (100 is exact). Default {quality: 90}.

Also takes signal, onProgress, maxPixels, readAs, webgpu: shared options.

types

  • CaptureCompleteOptions

    Photographic capture's options with efforts 8 and 9 too.

  • CapturePhotoFidelity

    Exact by default. A maxError is integer 0–8. Quality 1–100 offers photographic capture, with 100 normalized to exact: each photo gets its own coding, aimed at the measured SSIMULACRA 2 look that number names. Fidelity is one exclusive choice. The picture itself continues to describe its samples.
