api

advance

Advance the latest checkpoint within this call's budget, awaiting every new part's write. Invalid budget.ms or budget.reads, or a missing verifier for a verifying checkpoint, refuses JXL_OPTIONS.

function advance<Operation extends ResumableOperation>(checkpoint: Checkpoint, options: AdvanceOptions<Operation>): Promise<AdvanceResult>

AdvanceOptions

  • budget? {readonly ms: number; readonly reads?: number}

    ms: positive milliseconds, at most 60000. Defaults to {ms: 30}. A call advances at least one step. reads: the store reads a call may make, for a host that allows few calls a request (none by default).

  • verify? typeof verify

    jpegxl/verify's verify, for a job started with it (an advance without it refuses with JXL_OPTIONS).

finish

Assemble a finished checkpoint's output and return the ordinary result, or variants' list. verification is present only when start asked for it. A verify job returns its receipt without reading either image. finish does no whole-file hashing, decoding or scoring. An assembled result beyond memoryBytes or a failed allocation refuses JXL_MEMORY. Incomplete or missing saved output refuses JXL_INPUT.

function finish<Operation extends ResumableOperation>(checkpoint: Checkpoint, options: FinishOptions<Operation>): Promise< Operation extends typeof verify ? VerificationReceipt : VerifiedResult<Awaited<ReturnType<Operation>>>>

FinishOptions

  • input InputOf<NoInfer<Operation>>

    The input start was given, the same descriptor: a checkpoint of another original is refused.

  • signal? AbortSignal | undefined

    Aborts this call. The job stays resumable from its last checkpoint. Explicit undefined is accepted.

start

Start the operation over the stored original and return its first durable checkpoint. Invalid operation, store or verification settings refuse JXL_OPTIONS. An operation without resumable steps refuses JXL_UNSUPPORTED. Missing decoder or verification setup refuses JXL_PLATFORM.

function start<Operation extends ResumableOperation>(options: OperationContext<Operation> & StartOptions<Operation>): Promise<Checkpoint>

OperationContext

  • operation Operation

    Pass the imported verb itself: capture, recompress, restore, encode, fit, variants or verify.

  • store ResumableStore

    Where the original, parts and checkpoints live. Every call of one job gets the same store.

  • memoryBytes? number

    Optional memory admission, in bytes, on each call. Uses measured working sets with 10% headroom and 32,000,000 bytes for the host. Unmeasured sizes, source types or verification choices refuse with JXL_MEMORY. Measurements cover PNG8 encode/fit and baseline 4:2:0 JPEG recompress. On advance it also bounds what a call holds of the job's saved values (JXL_MEMORY past it). Without it the host's allocation is the limit.

workerAdmission

The next measured size at least the requested pixel count, with estimated bytes. null without a row. Invalid dimensions, kind or operation value refuse JXL_OPTIONS. An operation without resumable steps refuses JXL_UNSUPPORTED.

function workerAdmission<Operation extends ResumableOperation>(options: {readonly operation: Operation; readonly options?: ResumableOptions<NoInfer<Operation>>; readonly width: number; readonly height: number; readonly kind?: ResumableInput['kind']}): WorkerAdmission

types

  • ResumableFunction

    A callable carrying its own resumable steps. The private marker exists only in the type system.

  • ResumableInput

    The immutable original held by the store. generation is a nonempty host identifier (at most 256 characters), and sha256 is the original bytes' SHA-256 as 64 lowercase hexadecimal characters, without a prefix. JPEG operations read file bytes. Capture reads straight RGBA8 rows described by ResumablePixels. Encode, fit and variants and verify read either, an encoded file named by kind 'file' (ResumableFile). Encode and fit also read a JPEG XL whose decode is the picture (ResumableDecode).

  • ResumablePixels

    Straight RGBA8 rows: positive pixel dimensions. byteLength is width * height * 4.

  • ResumableFile

    An encoded file (JPEG, PNG, WebP and the others an upload reads), read in the job's own steps.

  • ResumableDecode

    A stored JPEG XL, such as a JPEG's lossless one, whose picture is its decode: jpegxl/decode's decode, set once with configureDecoder(decode) from jpegxl/verify. The job encodes the decoded pixels, as encode() of them would.

  • PartRef

    An immutable stored part, at most 1 MiB. hash is its SHA-256 as 64 lowercase hexadecimal characters.

  • ResumableStore

    write keeps one part. writeMany keeps a call's parts in one request. A store has either, or both.

  • Checkpoint

    An opaque JSON record returned by start or advance. Persist it unchanged after the call's writes finish, using revision to guard the host's save, and pass the latest saved record to the next call. The driver rejects stale, changed or foreign records. Keep checkpoints where only your service writes them. The original and parts may be in any store, and every byte read back is checked. The brand exists only in the type system.

  • ResumableOperation

    Resumable verbs: encode/fit/variants from jpegxl or jpegxl/upload, capture from jpegxl/capture or jpegxl/capture-complete (every effort), recompress/restore from jpegxl/jpeg, and verify from jpegxl/verify.

  • ResumableCaptureOptions

    Capture's data-only saved options. Per-call cancellation is supplied to advance or finish.

  • ResumableCaptureCompleteOptions

    capture-complete's data-only saved options: its rectangles too.

  • ResumableJPEGOptions

    Recompression preserves the JPEG's coefficients and takes these ordinary JPEG settings.

  • ResumableRestoreOptions

    Restoration admits only the pixel bound in its saved plan.

  • ResumableVerificationOptions

    Verify a separately uploaded candidate against the stored original. The host stores its nonempty byte parts under their SHA references before start. Result metadata declares a promise to check. It supplies no trusted evidence.

  • ResumableUploadOptions

    encode, fit and variants save their data options: callbacks, signals and helpers belong to each call.

  • ResumableOptions

    The data options an operation saves in its plan. Callbacks and signals belong to each call.

  • StartOptions

    The operation alone determines the admitted source and option shapes.

  • FinishOptions

    jpegxl/verify's verify: verify in the advances and return the whole-file verifier's receipt at result.verification. The plan saves that verification was chosen. Pass the same verify to every advance. The host supplies a decoder through configureDecoder where needed.

  • AdvanceOptions

    Aborts this call. The job stays resumable from its last checkpoint. Explicit undefined is accepted.

  • AdvanceResult

    jpegxl/verify's verify, for a job started with it (an advance without it refuses with JXL_OPTIONS).

  • WorkerAdmission

    Whether a resumable job runs within a Cloudflare Workers isolate's 128 MB, from jpegxl's measured table: the Node estimate (total peak minus bare runtime) x 1.1 <= 96,000,000 B, admitted only where every measured size up to the first at least this large was admitted. Pass the imported operation function (encode, recompress, etc.), never the operation name as a string. The answer rests on the next measured size bucket at least width x height pixels, which can be larger than the requested picture. A size without a matching row is not admitted.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
