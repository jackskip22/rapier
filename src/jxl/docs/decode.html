api

close

Ends this module's worker and helpers. The next call starts them again.

function close(): Promise<void>

configure

This module's settings for the calls that follow. In a browser they are its queue's: the module runs in its own file's worker, from a page or nested in a worker of the page's own. configure before the first call, or again once close() has resolved. In place (Node, Deno, Bun, edge hosts, a page's own worker) it takes the same keys: maxPixels, and maxPendingJobs bounding the calls pending at once. No worker starts and nothing is copied there, so the worker settings and maxPendingBytes have nothing to act on. Configuring while a call runs refuses JXL_OPTIONS.

function configure(settings?: Omit<CodecConfig, 'webgpu' | 'helpers'>): void

decode

The whole picture decoded: a page's calls run in its own worker. Calls in a worker, Node and edge hosts run in place. Every decoder part and the Brotli dictionary are in this module, so nothing loads after its import. A cut or malformed file refuses JXL_DECODE or JXL_INPUT. An invalid option JXL_OPTIONS, a limit JXL_LIMIT, unsupported HDR conversion JXL_UNSUPPORTED, and unavailable memory JXL_MEMORY. Decoded frames are in result.frames. result.animation gives the tick rate and loop count. A literal format types result.data: {format: 'uint8'} gives a Uint8ClampedArray.

function decode<F extends NonNullable<DecodeOptions['format']> = 'auto'>(input: Uint8Array | Blob, options?: DecodeOptions & {format?: F}): Promise<DecodedImageOf<F>>

DecodeOptions

  • format? DecodeFormat

    Auto selects 8/16-bit integers from the source depth, or float for floating/over-16-bit input. For a canvas, pass {format: 'uint8', colorSpace: 'srgb'}: new ImageData(data, width, height) takes only 8-bit data.

  • colorSpace? 'original' | 'srgb' | 'linear-srgb' | 'display-p3' | 'rec2020' | 'xyb' | DecodeColorTarget

    Original preserves the source color meaning. Select sRGB or another SDR target for a display image: PQ and HLG pictures are tone-mapped to 255 nits using ITU-R BT.2408 (PQ) or BT.2100 HLG OOTF with gamut mapping matching libjxl 0.13.0. Converting HDR to another HDR transfer or XYB refuses JXL_UNSUPPORTED.

  • applyOrientation? boolean

    Apply all eight orientations to every output plane. Default true.

  • unpremultiplyAlpha? boolean

    Unassociate RGBA RGB values when the first alpha channel is associated. Default false. Native planes are preserved.

  • renderSpotColors? boolean

    Apply signalled spot-color swatches to RGBA. Default false. Native extra channels are preserved.

  • planes? boolean

    Also return the float32 color planes beside RGBA. Default false: planes is [].

  • region? DecodeRegion

    Decode only this rectangle of the picture as returned (after orientation when applyOrientation): whole pixels inside it. The result, every frame and its planes are the rectangle, equal to the same pixels of a whole decode. Frames and groups the rectangle does not reach are not decoded.

  • partial? boolean

    A file cut short (a download in progress) decodes to the picture at 1:8 from the LF its bytes hold, instead of being refused: the result is ceil(width / 8) x ceil(height / 8) and says partial. A whole file decodes as without it. Plain VarDCT frames without alpha only. Anything else cut short is refused. Not with region. Default false.

  • components? boolean

    Decode packed raw color components instead of RGBA: 1 sample per pixel for grayscale, 3 for RGB or XYB, and 4 for CMYK (C, M, Y and the black extra channel), with no RGBA buffer allocated. Extra channels such as alpha stay in extraChannels. Not with unpremultiplyAlpha or renderSpotColors. Default false.

  • firstFrame? boolean

    Decode only the first displayed frame of an animation, stopping before later frames are read. Zero-duration layers that build frame 0 are still composited. Default false.

  • onFrame? (frame: DecodedFrame, index: number) => void | PromiseLike<void>

    Called with each shown frame and its index, in order, as it is composited. The frame is then dropped from the result, which keeps only the first, so an animation of any length decodes in the memory of a few frames. The next frame is not rendered until the returned promise settles, so a slow consumer holds the decode back. A throw or rejection fails the decode with that error. The frame is the decoder's own: copy it to change it. Where decode runs in place (Node, a worker, an edge host). A call from a page refuses JXL_OPTIONS. Not with region or partial.

Also takes signal, onProgress, maxPixels: shared options.

prepare

Compiles the WebAssembly kernels before the first decode. Decoding requires WebAssembly with SIMD. Without it this and decode() reject with JXL_WASM.

function prepare(): Promise<void>

supported

Whether this realm decodes: WebAssembly with SIMD compiles here. supported('webgpu') is false: the decoder runs nothing on WebGPU. Other feature names refuse JXL_OPTIONS.

function supported(feature?: 'webgpu'): Promise<boolean>

types

  • DecodeOptions

    What decode takes: output format, color space, orientation, region and the like, with the limits and JobOptions.

  • DecodedImage

    header is the whole file's image header, as decode parsed it: header()'s fields for the same file, plus icc, the file's own profile (header() reads no profile and may read only the file's first bytes). metadata (Exif, XMP, JUMBF) is inspect's detail, as everywhere.

  • DecodedImageOf

    decode()'s result for the format asked: 'uint8' gives a Uint8ClampedArray, 'uint16' a Uint16Array, 'float32' a Float32Array. 'auto' or no format, any of the three.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
