acceptsJxl

Whether an Accept header prefers image/jxl to alternative (RFC 9110 12.5.1), as serve decides. Default image/jpeg. With a string Accept header, a non-string alternative refuses JXL_OPTIONS.

function acceptsJxl(accept: string | null | undefined, alternative?: string): boolean

serve

A file from recompress served to every client: image/jxl where the request accepts it, else the exact original JPEG, with Vary: Accept, an ETag per representation, Cache-Control, Content-Length, 304 and HEAD. With a node:http response, a refusal first answers it 500, so no client waits. Handle the promise. Invalid requests and options refuse JXL_OPTIONS, oversized pictures JXL_DIMENSIONS, and missing JPEG reconstruction data JXL_RECONSTRUCTION. Caller bytes use plain Uint8Array. SharedArrayBuffer backing is refused with JXL_INPUT.

function serve(stored: Uint8Array | Blob, request: ServeRequest, options?: ServeOptions): Promise<Response>; function serve(stored: Uint8Array | Blob, request: ServeRequest, response: ServeNodeResponse, options?: ServeOptions): Promise<undefined>

ServeOptions

  • cacheControl? string

    Cache-Control header (default 'private, no-cache', pass 'public, max-age=31536000, immutable' for public, content-addressed URLs).

  • etag? string

    The stored file's entity tag. Each representation gets its own (-jxl, -jpeg). Default: the file's SHA-256, computed once per stored Uint8Array or Blob (pass a new array, or your own etag, after changing its bytes, a large file's own key or version is a cheap etag).

  • maxPixels? number

    The largest picture served, in pixels. None by default. A larger one refuses JXL_DIMENSIONS.

  • width? number

    To an image/jxl client, the smallest of the file's sizes (1:8, 1:4, 1:2, 1:1) at least this many pixels wide, cut from the file without decoding (jpegxl/metadata slice). A file with no passes to cut is served whole.

  • maxBytes? number

    To an image/jxl client, the largest of the file's sizes in at most this many bytes. None refuses JXL_LIMIT.

  • responsive? boolean

    Take width from the client's Sec-CH-Viewport-Width (or Viewport-Width) times its DPR, and Vary on them.

  • fallback? {type: string; bytes: Uint8Array | Blob | (() => Uint8Array | Blob | Promise<Uint8Array | Blob>)}

    For a client that cannot read JPEG XL when the stored file holds no JPEG reconstruction: these bytes (or a function returning them, called only then) are answered as type, with Vary: Accept. Without it that case refuses JXL_RECONSTRUCTION.

Also takes signal: shared options.

types

  • ServeOptions

    How serve answers: cache header, entity tag, pixel bound and abort.

  • ServeRequest

    A request: a Web Request, or anything with method and headers (a Headers object or a header record).

  • ServeNodeResponse

    node:http's response: status, headers and body are written to it.

  • Bytes

    Library-produced bytes own an ArrayBuffer. Caller byte inputs accept plain Uint8Array.

  • CodecError

  • ErrorCode

    The code every refusal carries, by what the caller does next. The call: JXL_OPTIONS (an option is unknown or its value is not allowed). The input: JXL_INPUT (the picture or bytes are missing, empty, not what the call takes, or a file that changed while it was read), JXL_DIMENSIONS (the picture is over maxPixels or the side limit), JXL_JPEG (the bytes are not a JPEG), JXL_DECODE (the file is not a valid JPEG XL), JXL_RECONSTRUCTION (no JPEG reconstruction data), JXL_TARGET (a measured fidelity this version cannot reach), JXL_PLATFORM (an input this realm cannot decode, or a host API this call needs, a missing decoder's message names configureDecoder or the effort that runs here). A bound: JXL_MEMORY (not enough memory for this picture here, or the queue's maxPendingBytes, maxPendingJobs), JXL_LIMIT (a parser's maxInputBytes or maxBytes, a written file over its byte bound, or capture's rectangle budget). The host: JXL_WASM (no WebAssembly with SIMD here), JXL_WEBGPU (webgpu: 'required' and a job this version would run on WebAssembly: efforts 1-6, an exact file, no usable device, a device that failed the job, or a route this version runs on WebAssembly only), JXL_WORKER (the worker could not start, stopped or failed, its message names the fix: a blocked worker-src, a start that timed out), JXL_IO (a Blob or an image request could not be read). The lifecycle: JXL_CLOSED (the module's queue is closed). A job canceled through its signal rejects with that signal's reason, an AbortError DOMException unless you passed one. Not done by this version: JXL_UNSUPPORTED, a valid request or file asking for something this version does not do. The setup commands: JXL_SETUP (add or remove cannot change a project's files safely. Its message names the step to do by hand). Ours: JXL_INTERNAL (a fault in jpegxl itself). A code keeps its meaning through 8.x. A later 8.x may add one.
